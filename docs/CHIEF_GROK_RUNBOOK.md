Give the block below to the Chief Grok Bot as one instruction. It authorizes deployment and observation, not custody or discretionary trading.

```text

Hard boundaries:

- Never run two engine processes. Never solve EADDRINUSE by changing the port.
- Never pull, build, or restart over an open or closing live position. Reconcile it first. A code upgrade is not an exit strategy.
- You may pull/build/test, change only DESK_MODE between shadow and live in the existing protected .env, manage the one service, inspect local health/ledger/logs, and disarm or engage KILL.

Do this in order:
1. Before mutating files or processes, read the running /api/health and /api/snapshot plus the ledger. If the current live wallet has an `open` position, disarm and use the existing engine's KILL path, then reconcile the exit on chain. If it has a `closing` position or an unreconciled/submitted transaction, do not issue another sell and do not restart; reconcile the signature and wallet balances. Stop and report `LIVE_POSITION_BLOCKS_UPGRADE` until every current-wallet live position is confirmed closed or explicitly reconciled. Never infer closure from a dashboard message alone.
2. In the existing solid-octo-engine checkout, record the current public commit and public expected signer address without displaying any secret. Preserve .env, the SQLite ledger, and the existing keypair file. Inspect tracked changes before pulling. If `config/policy.json` was locally changed to put the `$1,000,000` paper budget in `maxDailySpendUsdCents`, save a non-secret diff outside the checkout, restore only that tracked policy file to the current commit, and leave every secret/ledger/signer file untouched. Require the incident regressions for loss-stop, bounded pre-broadcast exit retry, no retry after ambiguous broadcast, hold-risk uncertainty, hard hold-risk failure, and Pump 6002/6003 classification to pass. Find the owner of port 8787 and stop only a verified old Solid Octo process/job. Load exactly one com.solid-octo-engine job. Do not also run npm start.

Confirm policy version 3: `stopLossPct=5`, `takeProfitPct=20`, `takeProfitSellFraction=1`, `maxDailyShadowSpendUsdCents=100000000`, and `maxDailySpendUsdCents=5000`. Confirm fresh slot heartbeats, healthy price sources, RPC max 8 RPS, queue recovery to zero, no recent 429, no recurring parser/catch-up exception, exact-mint terminality, and bounded event growth. For Token-2022 candidates, require holderSource=helius_program_accounts_v2, a positive holderAccountCount, getProgramAccountsV2 in RPC telemetry, and no getTokenLargestAccounts call for that mint. Then have the human release KILL locally without arming. Keep shadow running for at least 30 minutes and until at least 10 unique exact-mint Risk runs complete, whichever is longer. Given the current Pump stream, require at least 10 completed Token-2022 Risk runs specifically. Require zero duplicate buy intents, zero KILL-on instant paper dumps, zero process crashes, zero EADDRINUSE, no recurring 403/429/timeouts, no "not a Token mint" error, and no unknown caused by malformed parsing. A Pump 6002 buy simulation rejection is a terminal candidate-local miss: confirm there was no broadcast, confirm live automatically disarmed, report it, and do not restart/remake. Pump 6003 sell simulation failures may be retried only by the engine's bounded fresh-intent path at fixed slippage. Never issue an extra sell when broadcast may have occurred. On stale stream, recurring RPC failure, the configured hold-risk uncertainty threshold, signer mismatch, ambiguous broadcast, reconciliation mismatch, or missing position state: keep/engage KILL, report the exact evidence, and claim no fill without a confirmed signature plus reconciled ledger position.
